# ProgreSQL release workflow

Used by the Codex `deploy` skill. Invoke `$deploy` (or select **deploy** from `/skills`) to release this app. An invocation authorizes the version update, commit to `main`, push to `origin/main`, and deployment to **https://progresql.cotsakis.com**. Merely installing or reading the skill is not a deployment request. Honour any explicit dry-run or other constraint.

## Inspect and select the version

1. Locate this repository by its `progresql` package name, `wrangler.jsonc`, and `origin` repository `RyanCotsakis/progreSQL`. Inspect branch, working tree, staged changes, and the current `package.json` version. Fetch `origin/main` before integrating changes. Preserve unrelated user edits; do not force-push, discard edits, or overwrite remote work. Switch/integrate onto `main` without losing work; stop if conflicts need a decision.
2. Find the latest actual version change with `git log --format=%H -G '"version":' -- package.json`, then inspect candidate diffs and the complete changes since that release commit, including staged, unstaged and intended new files. Do not infer scope only from the latest commit or the last modification to package.json. If there are no unreleased changes, verify the existing version instead of making an empty bump/commit.
3. Choose a patch for fixes, copy, and small usability improvements; a minor for substantial backwards-compatible features; a major for breaking user/data/API changes. Briefly explain the choice. If a release bump is already prepared, validate and reuse it rather than bumping twice. A failed push or deployment should resume the same version and commit.
4. Keep `package.json`, the root version and `packages[""].version` in `package-lock.json`, `APP_VERSION` in `app/main.py`, and the footer version in `src/App.tsx` synchronized. Do not alter dependency versions or the legacy Python package metadata just to bump the app.

## Validate and commit

5. Run `npm run build`, `npm test`, and the existing desktop/mobile browser flows for UI changes. On Windows the installed browser is selected with `$env:PW_CHROMIUM_CHANNEL='msedge'` before `npx playwright test`. Use the isolated test database; never create test workouts in production. Run Python tests when migration/legacy/auth conversion code changes. Re-run affected checks if implementation changes after testing.
6. Review the exact intended diff and new files. Scan candidates against local real credential values without printing the values; inspect suspicious token/private-key/credential-URL literals. Check staged content again before committing. Only placeholders and clearly fake test credentials may be checked in. Keep `.streamlit/secrets.toml`, `.dev.vars*`, `.env*`, `.wrangler/`, exports, databases, QR codes, and test/browser artifacts out of Git. Cloudflare account/database IDs are identifiers, not secret values.
7. Validate `node scripts/check-deploy.mjs` and `npx wrangler deploy --dry-run --secrets-file .env.auth-upload.json`. This local ignored JSON supplies existing Worker secrets; never echo it or pass its values on the command line. If missing, `scripts/prepare_worker_auth.py` can derive it from the existing local Streamlit secrets without changing the password or TOTP enrollment.
8. Stage only reviewed release files, run `git diff --cached --check`, commit on `main` with a descriptive message including the version, and push normally with `git push origin main`. Confirm the pushed revision. On rejection, inspect and reconcile; do not force-push. Stop on a failed validation, commit or push before starting deployment.

## Publish and verify

9. Deploy the already-tested build using `npx wrangler deploy --secrets-file .env.auth-upload.json` (or `npm run deploy`, which rebuilds). Keep `workers_dev`/preview URLs disabled and the existing custom domain, database, authentication and Free plan. Do not rerun data import, enable paid upgrades, or bypass approval controls.
10. Wait for the deployment result. Verify the live HTTPS homepage references the expected JS/CSS assets and compare their hashes with local `dist` files. Verify HTTP redirects to HTTPS and unauthenticated `/api/data` returns 401. Use a normal browser user agent for automated HTTPS checks; this zone rejects Python's default user agent. Never disable certificate validation. If system DNS is stale, consult current public DNS and disclose any diagnostic resolver override rather than hardcoding an old IP.
11. Report the app version, commit, push result, public URL, tests and any real limitation. Do not report success solely from an upload message. If deployment fails after the push, preserve the commit/version and report the failed stage; retry only a transient failure, not an approval denial.
